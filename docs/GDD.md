# Dead Feed — Game Off 2026 GDD（草案）

## 概要

玩家坐在 1980 年代苏联某秘密设施外的操作台前，通过机载摄像头和残存的监控画面遥控机器人深入被封锁的地下区域。恐怖感来自未知、断断续续的信息，以及不同视角之间的配合，而不是来自怪物。

## 主题解读：SHIFT

SHIFT 在这款游戏里是核心操作，不只是背景设定，一共落在四层：

- **切换视角（perspective shift）**：在机载画面和各路监控之间来回切换，是整个游戏的主要动作
- **Shift 键**：机载 / 监控的切换就绑在 Shift 键上，接住官方给的提示
- **信任的偏移**：后期画面会说谎，玩家从信任监控转向怀疑它
- **结局的视角反转**：最后一路监控拍到的是操作台前的玩家自己，观察者变成了被观察者

## 设计支柱

目标：恐怖来自未知和断续的信息，而不是怪物。

| 支柱 | 内容 | 对应威胁 |
| --- | --- | --- |
| 未知 | 不给地图，拍到哪补到哪；旧图纸与实际对不上 | 回视者 |
| 断续 | 低帧率监控；掉帧、雪花、只剩声音 | 帧间者 |
| 视角协作 | 单靠一个画面解不开；双机互为对方的眼睛 | 听声者 |

基础：Shift 切换画面 · 3D 灰盒 + CRT · 声音设计。每个设计决定都要能落到三个支柱之一上。

## 核心玩法与操作

玩家同一时间只能看一路画面，也只能操控一台机器人，但这两个选择是独立的。核心循环：切画面确认位置 → 在脑子里转换方向 → 操控前进 → 信号中断或离开画面 → 再找下一路画面。

### 两类摄像头与分离感（核心亮点）

两种摄像头刻意做成互补，而且差距要大。**透过固定监控遥控远处一个小小的机器人，那种分离感是这款游戏的核心亮点**，地图和场景都围绕它来设计。

| | 机载摄像头 | 监控摄像头 |
| --- | --- | --- |
| 高度 / 角度 | 很低（离地 40～50 cm），平视 | 高处墙角，俯视 |
| 视野 | 窄（约 60°） | 广（约 90°） |
| 照明 | 只靠头灯，前方 3～4 米，其余全黑 | 红外夜视，整个房间都看得到 |
| 画质 | 清晰，有颜色（偏暗、去饱和） | 单色、低分辨率、有噪点 |
| 帧率 | 正常，走远或受辐射时卡顿 | 普通监控 5～8 fps；特定老摄像头 1～2 fps（帧间者专用） |
| 能做什么 | 读文字、看颜色和小物件、看得到桌子底下 | 看布局、路线、哪里不一样，看得到机器人自己 |
| 看不到 | 全局、身后、机器人自己 | 细节、颜色、遮挡物下面 |
| 画面上的元素 | 无 | 只有摄像头编号和时间戳（属于监控画面本身）+ 机器人朝向箭头 |
| 声音 | 履带和电机声，清楚、贴耳 | 远处闷闷的环境声 |

只有机载有颜色：颜色本身就是一种只有凑近才拿得到的信息，玩家也能一眼分出自己在看哪个画面。

加强分离感的手段：
- 监控装在高处、远处，画面里的机器人只是一个小点
- 透过监控操控时，操作仍然相对机器人自身（前进 / 转向），靠朝向箭头在脑子里转换
- 切到监控时，机器人的声音变远变闷；切回机载，声音一下子贴到耳边

### 操控与观看分离

- 一组键切换**操控对象**（机器人 A / B，第 6 关起）
- 一组键切换**观看画面**（机载 / 各路监控）
- 这是「两台机器人互为眼睛」的前提：用 A 的镜头看着 B，同时操控 B

### 操作方案（初稿）

| 动作 | 按键 |
| --- | --- |
| 机器人移动（相对自身：前进 / 后退 / 左转 / 右转） | W A S D |
| 机载 ↔ 上一路监控（开局切到 CAM-1） | Shift |
| 直接选监控 | 数字键 1～9 或点击平面图上的摄像头 |
| 切换操控对象 | Tab |
| 交互（拧阀门、拉闸、读文件） | E |
| 头灯开关 | F |

使用密码面板时，数字键用来输入密码，不切换监控。

### 切换的体验要求

- 切换时有 0.5～1 秒雪花和继电器咔哒声，每次切换都是一个决定，也是惊吓的时机
- 机器人身上有前方小灯；监控画面里始终显示机器人朝向箭头
- 平面图是残缺的，摄像头拍到哪里就补全哪里；不显示机器人位置
- 关卡要短，重来要快，迷惑感得是谜题，而不是操作烂

### 电缆

机器人拖着电缆。前几关不做任何限制，控制难度；后期关卡（第 5～6 关）才引入电缆长度限制、被卡住、被扯动。

## 威胁与惊吓

威胁一共 3 种，每种对应一个设计支柱，只在特定区域出现。大部分时间玩家面对的是空荡荡的未知。

| 威胁 | 规则 | 服务的支柱 | 出没区域 |
| --- | --- | --- | --- |
| 听声者 | 看不见，循声而来。机器人移动、发电机都会引它过来；应对方式是停住，用监控确认它的位置 | 视角协作 | 断电区及之后的暗区 |
| 帧间者 | 只在低帧率监控的帧与帧之间移动，每一帧离你近一点；可预测，所以公平 | 断续 | 实验室 set piece、最后一关 |
| 回视者 | 在画面里盯着它太久，它会转头看镜头，那路画面永久断掉，地图上那一块变回未知 | 未知 | 档案库之后 |

背景压力：辐射只以机载画面噪点和盖革计数器的形式存在，营造氛围，基本不构成惩罚。

### 统一规则

- **先有预兆，再有本体**：每种威胁第一次出场前，先通过声音、文件或某一帧画面给出暗示，让玩家自己猜规则
- **区域限定**：每种威胁只在它的区域出现
- **只损坏，不秒杀**：被击中就掉一个功能（头灯、镜头裂纹、履带变慢、某路监控），功能全掉光才回检查点
- **脚本优先**：威胁都做成区域触发、行为简单的脚本，不做复杂 AI

### 惊吓预算

- 全程 4～5 次脚本化惊吓，都放在一段平静之后，与威胁系统分开
- 主要手法：低帧率画面里多一帧或少一帧、切换时雪花散去的瞬间、机载和监控看到的不一致
- 其余靠假警报：声音、闪烁、某路信号突然断掉

## 关卡结构

6 关加一个结局，每关 2～4 分钟。每关引入一个新机制，并且至少有一个「单靠一个画面解不开」的协作谜题，避免变成步行模拟器。

| # | 区域 | 新机制 | 协作谜题（示例） | 威胁 |
| --- | --- | --- | --- | --- |
| 1 | 控制室走廊 | 机载 + 监控，朝向相同（教学） | 监控找出哪张纸不一样，机载读出密码 | 无，只有环境和预兆 |
| 2 | 热室 | 镜像 / 旋转视角，开始在脑子里转方向 | 只能透过铅玻璃反光镜看到机械臂位置 | 无 |
| 3 | 断电区（暂缓） | 盲区 + 推算位置，配电箱恢复监控 | 恢复供电后才能看到盲区出口 | 听声者 |
| 4 | 实验室 | 自动转动的老式监控 | 监控看仪表读数，机器人拧阀门 | 帧间者（set piece） |
| 5 | 档案库 | 循环的假画面 | 机载看到的和监控对不上，拆穿假画面（时间戳重复 / 画面里没有你的机器人） | 回视者 |
| 6 | 最底层 | 发现旧月球车，双机互为眼睛 | 一台照明 / 盯住威胁，另一台摸黑操作 | 前面出现过的威胁组合 |
| — | 结局 | 最后一路监控拍到操作台前的玩家 | — | — |

第 6 关分两段：先是发现（监控里有东西在动，结果是当年的旧月球车），然后是双机协作进入秘密区域，并播放月球车存储里的最后一段录像。

各关详细设计见 `level-design.md`。

## 故事与世界观

虚构设施「Объект-17」位于 1980 年代苏联某封闭城市地下。当年一次事故后整个设施被封锁，派进去的调查队和遥控月球车都没有回来。玩家是新派来的操作员。

- **灵感来源**：切尔诺贝利清理期间苏联曾派遥控机器人作业，部分改自月球车技术，却被辐射烧坏。宇宙探索、核辐射、遥控机器人三者在历史上本就相连
- **设施是虚构的**：不用真实地名，剧情更自由，也避开敏感问题
- **叙事靠碎片**：用机载摄像头发现文件和录音，操作台显示翻译；信息本身也是断断续续的
- **主线**：控制室走廊 → 热室 → 实验室 → 档案库 → 最底层，逐渐发现实验对象与某次太空任务带回的东西有关
- **旧月球车**：它为什么又启动了是一个悬念；它存储里的最后一段录像揭示当年事故的真相
- **结局**：最后一路监控拍到的是操作台前的玩家自己，而你身后站着……

## 美术与声音方向

美术是弱项，所以风格选「粗糙即真实」的监控画面；声音成本低、效果大，是重点投入项。

### 美术

- **场景**：苏联粗野主义混凝土建筑，用 Godot CSG 方块灰盒搭建，配少量重复使用的道具（仪表盘、阀门、档案柜、管道）
- **画面处理**：CRT shader（扫描线、噪点、桶形畸变），监控单色低分辨率，角落时间戳和摄像头编号
- **操作台 UI**：绿色磷光显示器、西里尔字母标签、物理按钮风格，UI 本身就是美术的一部分
- **机器人**：简单几何体 + 前方朝向灯；实体用剪影、低多边形人形或一帧一帧的换模型来表现

### 界面原则（重要）

**Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.**

所有界面文字以英文为主。

### 声音

- 盖革计数器的咔哒声（随辐射变快）
- 无线电杂音、短波数字电台风格的广播
- 闷闷的俄语广播、继电器切换的咔哒声、履带的金属摩擦声
- 听声者区域需要可定位的 3D 音效
- 音效来源：免费素材库 + 自己的音频剪辑工具处理；提交前确认授权

## 范围、开发计划与风险

第一周只做一件事：验证「切换画面 + 在脑子里转方向」好不好玩，不好玩就当周调整。

### 优先级

1. **必须有**：机器人移动、机载 / 监控切换、CRT 画面、关卡 1、2、4、帧间者、基础音效、结局
2. **应该有**：关卡 3、5～6、听声者、回视者、假画面、双机协作、电缆限制、文件与录音
3. **可以有**：更多脚本惊吓（自由布置摄像头暂不考虑）

### 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 方向转换太迷惑，变成操作烂 | Gameplay 分 | 第一周做原型并让别人试玩；监控画面里始终显示机器人朝向箭头 |
| 威胁太少，被当成步行模拟器 | Gameplay 分 | 每关至少一个协作谜题 |
| Godot 3D 经验不足 | 进度 | 只用 CSG + 固定 Camera3D + SubViewport，不碰复杂光照和动画 |
| Web 导出性能或 shader 兼容性 | 可玩性 | 第一周就导出一次 Web 版测试；监控渲染到低分辨率 SubViewport，同一时间只渲染一路画面；控制动态光数量；Tab、Shift 在浏览器里的按键行为要实测 |
| 内容做不完 | 进度 | 按优先级砍内容，第 6 关可以缩成一个双机场景 |

### 里程碑

| 时间 | 内容 |
| --- | --- |
